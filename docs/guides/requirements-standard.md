# 需求文档管理规范

## 文档归属

当前需求文档放在 requirements，包含业务规则、交互和关键截图。guides 存流程与模板，reference 存原始输入；AGENTS.md 定义协作约束。澄清是完善需求的过程，不另存重复完整需求或过渡记录。

## 编写与更新

- 每个新会话的新需求建立独立规格；同一会话对该需求的进一步澄清更新该规格，避免重复副本。
- 每轮先使用提问工具明确业务规则，再同步文档、demo 和截图。未明确的事项在讨论中解决，不作为正式规格的待确认表交付。
- 文档开头显著说明本轮变化，包含目标、范围、角色、规则、交互、数据、异常边界和验收标准；使用[模板](requirement-template.md)。
- 为每轮澄清保留版本变更条目和实际验证范围；完整历史由 Git 保存，不复制旧规格留在目录中。
- 截图嵌入需求 Markdown，注明视口、部门和操作状态；只保留当前有效证据，旧图被替换且无引用后删除。原始设计参考与实际截图应区分。
- 校验页面效果、语法和文档图片链接，完成后自动 commit、推送并核对远端。

## 作废清理

替代旧文档时，先合并仍有效的条款，再删除旧文件并更新全部索引及引用。作废文档和过渡截图通过 Git 追溯，不为保留历史另建 archive 或 changes 副本。用户提供的原始参考材料不因需求升级而自动作废。

## 编号和创建日期

- 需求文件统一命名为 `REQ-NNN-YYYY-MM-DD-主题.md`，日期为首次创建日期，使用 Asia/Shanghai 日期。
- 文档标题包含需求编号，元信息分别填写需求编号、创建日期和更新日期；后续修改只更新更新日期和版本，文件名中的创建日期与编号不变。
- 编号按历史最大值递增，不复用已删除编号。旧 REQ-001～REQ-004 已退休，REQ-005 为此前的整合需求，REQ-006 为执行方案补充字段需求，下一项新需求使用 REQ-007。
- 索引列出编号、创建日期、更新日期和文档链接，README 等导航文件不分配需求编号。

## 页面素材交付

页面变更所需图片、图标等实际文件统一保存在 `demo/assets/`，使用相对路径，避免外网和临时资源依赖，并与页面代码同次提交推送。运行素材、原始设计参考和文档截图分别管理。页面变更验收需检查资源存在、HTTP 加载、离线可用及 Git 跟踪；内嵌 SVG/CSS 图形无需重复导出。本次仅补充流程规范，没有页面变化或新增素材。
