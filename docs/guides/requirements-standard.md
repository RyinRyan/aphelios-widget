# 需求文档管理规范

## 文档归属

当前需求文档放在 requirements，包含业务规则、交互和关键截图。guides 存流程与模板，reference 存原始输入；AGENTS.md 定义协作约束。澄清是完善需求的过程，不另存重复完整需求或过渡记录。

## 编写与更新

- 同一需求只保留一份当前规格；新独立需求才创建新文件，同一需求的进一步澄清更新当前文档。
- 每轮先使用提问工具明确业务规则，再同步文档、demo 和截图。未明确的事项在讨论中解决，不作为正式规格的待确认表交付。
- 文档开头显著说明本轮变化，包含目标、范围、角色、规则、交互、数据、异常边界和验收标准；使用[模板](requirement-template.md)。
- 为每轮澄清保留版本变更条目和实际验证范围；完整历史由 Git 保存，不复制旧规格留在目录中。
- 截图嵌入需求 Markdown，注明视口、部门和操作状态；只保留当前有效证据，旧图被替换且无引用后删除。原始设计参考与实际截图应区分。
- 校验页面效果、语法和文档图片链接，完成后自动 commit、推送并核对远端。

## 作废清理

替代旧文档时，先合并仍有效的条款，再删除旧文件并更新全部索引及引用。作废文档和过渡截图通过 Git 追溯，不为保留历史另建 archive 或 changes 副本。用户提供的原始参考材料不因需求升级而自动作废。
