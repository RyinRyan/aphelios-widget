## 背景与目标

用户需要在工作桌面集中查看来自研发作业系统的待办，了解工作项内容，并将适用事项交给 AgentSpace 执行，在同一页面查看任务状态及进入任务详情。

## 范围与非范围

范围包括部门及来源展示、类别筛选、待办列表、详情、单项和批量下发、Agent 任务状态和跳转。现阶段交付为离线交互演示；真实认证、源系统接口、后台任务服务、Webhook、Kafka 和 AgentSpace 对接不在当前 demo 中实现。

## 角色与前提

研发用户已登录工作台。实际部门应由可信身份机制提供；演示通过顶部选择器切换部门，不用于授权。用户访问研发数据使用源系统的现有认证；空间执行方案的访问和管理遵循 REQ-003。

## 场景与交互

1. 用户打开页面，查看当前部门、来源系统和待办；总数徽标与当前部门全部对象数量一致，不固定写死；可按类别、状态、优先级筛选并分页。
2. 悬浮或键盘聚焦待办标题预览编号、标题和描述；点击标题或更多按钮打开详情。详情显示编号、标题、描述、来源和状态，并支持当前任务操作。触屏用户可点击打开。
3. 配置有效源对象地址时，列表与详情均提供“前往原系统”入口，在新标签页打开对应对象；无需先打开详情。无地址时说明尚未配置。
4. 用户可单项或多选下发 Agent；在详情中也能直接发起。执行方案选择见 REQ-002。
5. Agent 任务追踪展示任务及其状态；有实际任务详情地址时可跳转 AgentSpace。演示的入口仅显示说明。

## 业务规则与数据

| 类别 | 公共产品开发与IT装备部 | MAE-CN产品部 |
|---|---|---|
| RR | edevops | CoreALM |
| FE / IR | FE：edevops | IR：CoreALM |
| SR | 不使用 | CoreALM |
| US | edevops | CoreALM |
| DTS | dts | dts |
| MR | codehub | codehub |

选择“全部”时显示该部门所有类别及其来源；选择特定类别时只显示该类别的来源。MAE-CN 不显示 FE，使用 IR 并增加 SR。

部门差异按[REQ-004 部门差异化 Widget 展示](REQ-004-department-widget-configuration.md)组织：复用通用交互框架，通过部门业务配置确定对象类别、来源、展示字段及业务操作。部门不替代 AgentSpace 空间；执行方案按空间和对象类别选择。

用户确认 Agent 任务展示状态为**分配中、执行中、失败、已完成**，不展示执行百分比。尚未下发的待办显示“待处理”，不作为 Agent 状态。本规格规定页面展示状态；后台内部状态到展示状态的适配不属于当前离线演示范围，不能将所有内部异常直接当作失败。

根据后台设计 V2.0，Widget 直接调用研发系统人机接口获取业务数据；AiAgentManageService 保存 Agent 任务台账、发布统一 Webhook 并消费 Kafka 状态。已获 AgentSpace taskId 时后台生成详情地址。该文档为输入参考；当前 demo 不实施其接口。

## 响应式布局

按可用宽度切换布局：宽屏使用列式列表，中等宽度使用摘要与状态操作两层布局，手机宽度保留摘要和紧凑操作区；不逐字段堆叠。任务追踪在空间不足时上下排列。验收同时检查信息密度、层级、留白和操作可达性，不能仅检查溢出；发现问题立即调整策略并复测。

## 异常与边界

无匹配数据时展示空状态；来源地址不存在时不提供虚假跳转；无可下发项时提示用户。部门切换清除选中项。真实服务的失败恢复、权限响应和状态延迟处理不属于当前离线演示范围。

## 验收标准

- [ ] 演示：两个部门切换后，类别及来源符合上表；类别筛选同步改变来源展示。
- [ ] 演示：待办详情可用鼠标、键盘及点击操作打开，显示完整编号、标题和描述，且可直接发起下发。
- [ ] 演示：任务状态不显示进度百分比；待处理和 Agent 任务状态可区分。
- [ ] 演示：无真实来源地址时显示未配置；模拟操作不触发外部请求。
- [ ] 边界：页面不将模拟身份、事件和状态表述为真实集成。
