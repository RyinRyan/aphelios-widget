## 背景与目标

不同部门使用的业务对象及来源系统存在差异。Widget 识别用户部门后，通过部门业务配置组合适用页面，复用通用交互能力，支持后续扩展部门和对象场景。

## 范围

本规格明确部门差异的组织方式、已确定的类别及来源映射、展示边界，以及与空间执行方案的关系。实际身份接口、业务接口协议和配置服务部署不属于本规格的实现范围。

## 设计结构

```text
当前用户部门 → 部门业务配置 → 对象类别、来源、展示字段、业务操作
                                  ↓
                         通用 Widget 交互框架
                                  ↑
当前 AgentSpace 空间 → 该空间、该类别的启用执行方案
```

Widget 通用能力包括列表、筛选、分页、多选、详情、下发和任务追踪。部门业务配置决定对象类别、各类别的数据来源、展示字段和可执行操作。现阶段已确认的差异为类别及来源映射，两个部门使用同一套通用列表和详情交互。

部门具有独特业务流程时，在对应对象场景增加专用交互，通过业务配置选择；不为每个部门复制整套 Widget，也不将部门判断散布到各个按钮和弹窗中。

## 部门业务配置

| 对象类别 | 公共产品开发与IT装备部 | MAE-CN产品部 |
|---|---|---|
| RR | edevops | CoreALM |
| FE | edevops | 不显示 |
| IR | 不显示 | CoreALM |
| SR | 不显示 | CoreALM |
| US | edevops | CoreALM |
| DTS | dts | dts |
| MR | codehub | codehub |

对象类别具有独立业务含义。MAE-CN 使用 IR，不使用 FE；真实数据接入时分别查询相应对象，不通过修改 FE 编号伪造 IR。

来源系统返回的数据按通用展示结构组织，至少提供对象类别、编号、标题、描述和来源系统；存在真实源对象地址时提供跳转入口。不同来源中编号相同的对象应结合来源及类别区分，不能仅以显示编号作为跨系统唯一标识。

## 场景与交互

1. Widget 获得当前用户部门后，加载对应部门的业务配置，展示适用对象类别及数据来源。
2. 类别筛选只显示该部门使用的类别；“全部”只包含该部门适用对象。
3. 选择“全部”时显示该部门各类别的数据来源；选择单一类别时只显示该类别的来源。
4. 用户使用相同的列表、预览、详情和下发交互。详情中的来源系统和跳转地址来自当前对象。
5. 用户下发时，按当前 AgentSpace 空间和对象类别获取启用的执行方案，行为遵循 REQ-003。

## 部门与空间的关系

部门用于确定业务对象、来源和相应页面展示。AgentSpace 空间用于确定执行方案归属、共享范围和管理权限。两者独立：相同空间中的不同部门用户可以使用该空间适用类别的方案；相同部门用户处于不同空间时，分别使用所属空间的方案。

部门切换不改变当前空间，也不创建、迁移或删除空间方案。可用方案取决于当前空间与当前对象类别，不能以部门名称替代空间标识。

## Host 画布与组件边界

演示页面模拟 AgentSpace Host。顶部只提供演示环境配置，部门选择器仅模拟用户部门。当前部门、来源、类别筛选及执行方案配置入口归属于相应 Widget。真实运行由可信用户上下文识别部门，演示选择器不参与权限判断。

## 演示边界

现有 demo 通过选择器模拟两个部门，使用本地示例数据和单个模拟空间。页面中的 FE 转 IR 样例转换只用于视觉演示，不代表真实对象转换规则。该演示不证明实际接口、身份识别或配置服务已经实现。

## 验收标准

- 两个部门分别展示映射表中的类别及来源；MAE-CN 无 FE，装备部无 IR、SR。
- 两个部门复用列表、详情、筛选、下发及任务追踪的通用交互。
- 筛选某类别时仅展示其来源，选择全部时展示当前部门所有适用来源。
- 当前对象详情展示其编号、标题、描述和来源；只有有效对象地址才提供来源跳转。
- 同一空间切换演示部门不清除该空间方案，方案按对象类别适用。
- 业务操作入口位于 Widget 内，顶部仅用于演示环境配置。
