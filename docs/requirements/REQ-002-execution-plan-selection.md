## 背景与目标

同一业务对象可能由不同角色执行不同工作。MAE-CN 对 US 的例子包括 MDE 软件实现设计、SWE 代码实现、TE 测试设计与执行。下发时用户需要选择本次运行的 AgentSpace Workflow / Agent，避免同一对象始终触发固定任务。

## 范围与非范围

设计可复用的“业务对象 → 可用执行方案 → AgentSpace 执行实体”选择交互，MAE-CN US 作为首个场景。当前 demo 使用固定示例，尚无动态方案配置、角色识别、实际权限判断、任务参数表单或真实任务派发。

## 角色与前提

有权操作业务对象的用户；方案可用性、角色和 AgentSpace 配置来源待确认。角色可作为推荐依据，不能替代权限控制；是否限制用户选择需业务确认。

## 场景与交互

用户对适用待办点击“交给 Agent”，选择弹窗展示对象、工作目标、说明、对应 Workflow / Agent 及常用角色，选择后确认下发。任务追踪和待办显示所选方案。可用方案只有一个时如何快捷下发，以及多方案时的默认选择，待评审。

批量选择时，应选择所有对象共同可用的方案；无共同方案时引导用户分组。部分适用时应明确告知，不静默跳过。当前 demo 根据空间配置的启用方案展示选择项，涉及方案的混合类别提示分别下发；部分适用处理尚未实现。

## 业务规则与数据

执行方案标识、名称、工作说明、适用部门/对象、权限、所需参数及 AgentSpace 路由应由配置或服务提供。软件实现设计、代码实现、测试设计、测试执行及其 Workflow / Agent 名称在 demo 中均为示例，实际目标与映射待确认。

建议保留统一 Webhook，方案映射到可供 Event Task 过滤的路由。后台设计 V2.0 的创建接口由前端提交 eventType 和 taskName；将方案解析放到后台是设计建议，尚非已确认契约。

## 异常与边界

无可用方案、目标不可用、权限不足、缺少必要参数、重复下发和批量部分失败均需有明确提示；具体行为待确认。示例数据和模拟派发不代表实际执行成功。

## 验收标准

- [ ] 演示：对象类别配置启用方案后，下发时展示可选方案，未选择时不能确认。
- [ ] 演示：确认后待办及任务追踪能识别所选方案；不调用实际 AgentSpace。
- [ ] 演示：涉及配置方案的混合类别选择提示分别下发。
- [ ] 实际集成：可用方案、权限、目标路由与参数由确认后的服务契约提供，批量及失败场景按业务规则验收。
